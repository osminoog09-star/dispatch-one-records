# LAPD Records technical roadmap

Цель: развивать сайт, лаунчер, агент, Discord и админку маленькими безопасными срезами. Нельзя ломать рабочую синхронизацию, Supabase-логику, экспорт `docs/` и релизы лаунчера.

## Рабочие правила

- Перед задачей читать `WIP.md`, `HANDOFF.md`, `ROADMAP_TEAM.md`, `AGENTS.md`.
- Взять только один маленький срез и поставить WIP-lock.
- Не делать `git reset --hard`, `git checkout .`, `git stash` на всём дереве.
- Стейджить только свои файлы явными путями.
- `docs/` не редактировать руками, только через `python server/export_static.py`.
- После правок сайта запускать экспорт и smoke-check.
- После правок лаунчера запускать `python -m py_compile launcher/launcher.py launcher/setup_installer.py` и проверять UI глазами.
- Перед push: `git pull --rebase origin main`.

## Текущее состояние

- Сайт: Flask-шаблоны экспортируются в `docs/` для GitHub Pages.
- Вход/тикеты/редакторы: Supabase JS.
- Данные игры: агент и лаунчер синхронизируют pdComp/плагин с сайтом.
- Лаунчер: разделы есть, баннер обновлён, текстовые обрезания частично исправлены.
- QA сайта 2026-08-07: маршруты 200, внутренние ссылки проверены, целевые английские судебные хвосты убраны.
- Публичная загрузка лаунчера должна идти через `LAPD-Records-Launcher-Setup.exe`.

## Priority 0 - регрессии и публикация

Статус: постоянно.

Задачи:

- Проверять, что страница `/launcher` и регистрация ведут на установщик, а не на ZIP.
- Проверять, что GitHub release assets доступны: установщик, внутренний ZIP для автообновления, агент.
- После каждого push проверять GitHub Pages через 1-3 минуты.
- Вести `PLAYER_UPDATES.md` после заметных изменений.
- Сохранять записи для Claude в `HANDOFF.md` и при необходимости в отдельном QA-доке.

Готово, когда:

- Публичная ссылка скачивания не даёт 404.
- На сайте не видно старых ZIP-инструкций для обычного игрока.
- В `HANDOFF.md` есть краткое состояние для следующего агента.

## Priority 1 - связанные записи везде

Статус: следующий основной продуктовый срез.

Задачи:

- Проверить текущие связи: арест -> вызов, арест -> суд, арест -> досье, офицер -> записи.
- Добавить компактный блок “Связанные материалы” на страницы:
  - `case.html`
  - `callout.html`
  - `citation.html`
  - `court_case.html`
  - `file.html`
  - `officer.html`
- Все связанные сущности должны иметь ссылки: дело, вызов, штраф, суд, офицер, досье, карта.
- В хронологии показывать дату, тип, район/место, офицера и кнопку открытия.
- Не ломать существующие route names и экспорт.

Готово, когда:

- Из `/case/19/` можно открыть связанный вызов, суд, досье, офицера и карту, если данные есть.
- Из `/file/<name>/` хронология компактная, со ссылками и без сырого английского.
- Все новые внутренние ссылки проходят static link check.

## Priority 2 - статистика 24 часа / 7 дней / 30 дней

Статус: спроектировать и внедрить после Priority 1.

Задачи:

- Добавить серверные функции статистики по периодам:
  - аресты
  - штрафы
  - сумма штрафов
  - предупреждения
  - вызовы
  - суды
  - смены
  - часы службы
  - эвакуации/транспорт, если данные есть
  - изъятое/найденное, если данные есть
  - оружие/конфискация, если данные есть
- Добавить карточки “24 часа”, “7 дней”, “30 дней” на главную и/или отдельную страницу аналитики.
- Карта должна использовать те же агрегаты по районам.
- Не показывать пустую статистику без объяснения. Если данных нет, писать “данных пока нет”.

Готово, когда:

- На главной видно актуальную сводку за 24 часа, 7 дней и 30 дней.
- Значения совпадают с данными в таблицах.
- Пустые периоды выглядят аккуратно.

## Priority 3 - смены и Discord-отчёты

Статус: требуется проверка текущего пайплайна.

Задачи:

- Проверить текущую модель смен: начало, конец, длительность, тип смены.
- Ввести понятную группировку под 12-часовые смены: день/ночь или служебный интервал.
- Сделать итог смены офицера: аресты, штрафы, вызовы, суды, районы, часы.
- Добавить отправку отчёта смены в Discord после закрытия смены или после импорта.
- Добавить защиту от дублей при повторной отправке.
- Добавить лог/статус, если Discord webhook недоступен.

Готово, когда:

- Страница смен показывает не только список, но и понятный итог.
- Discord получает один отчёт на смену, без дублей.
- Ошибка Discord не ломает импорт данных.

## Priority 4 - карта, районы и координаты

Статус: карта есть, нужен второй слой точности.

Задачи:

- Проверить адаптивность карты на 1366x768, 1920x1080 и мобильной ширине.
- Подписи районов не должны перекрывать важные части карты.
- Hover/click легенды должен подсвечивать район.
- Ссылки вида `/map?zone=...` должны выделять район.
- Добавить поддержку `/map?x=...&y=...` после появления координат.
- В агент/плагин добавить сбор координат события, если это возможно без ломки.
- До координат использовать район/адрес как fallback.

Готово, когда:

- Карта не обрезается и не уезжает.
- Из записи можно перейти на район карты.
- После появления координат можно перейти на точку события.

## Priority 5 - поддержка и диагностика логов

Статус: первый фундамент готов, дальше диагностика логов и Discord-бот.

Готово:

- `/support` создаёт тикет с сайта без входа.
- `/support` делает локальную rule-based диагностику `.log/.txt` и добавляет сводку в тикет.
- Лаунчер помечает тикеты источником `launcher`.
- `/tickets` показывает единую очередь и источник обращения.
- `supabase/unified_tickets.sql` добавляет поля для Discord-каналов/тредов и защиту от дублей.
- `DISCORD_TICKETS.md` описывает контракт будущего Discord-бота.
- `discord_ticket_bot/` добавляет минимальный Discord-бот: кнопка тикета, приватные каналы, Supabase↔Discord комментарии, `!close`.

Этап 1, без AI:

- Страница диагностики логов поверх `/support`.
- Загрузка `.log` / `.txt`.
- Ограничение размера.
- Удаление секретов перед анализом.
- Rule-based поиск частых ошибок:
  - неверный позывной
  - pdComp не найден
  - нет доступа к папке
  - GitHub/Supabase/Discord ошибка
  - лимит GitHub Actions
  - не найден Vinewood/GTA
  - Python DLL / антивирус
- Кнопка “Создать тикет” с краткой сводкой.

Этап 1.5, Discord:

- Прогнать `supabase/unified_tickets.sql` в продовой Supabase.
- Заполнить `.env` для `discord_ticket_bot`.
- Запустить бота на машине/сервере и отправить `!ticket-panel` в канал поддержки.
- Проверить цикл: Discord тикет → сайт `/tickets`; сайт/лаунчер тикет → Discord-канал; ответ оператора → Discord.

Этап 2, с AI:

- AI включать только если правила не нашли ответ.
- Отправлять не весь лог, а вырезку важных строк.
- Не отправлять токены, ключи, webhook URL и личные пути.
- Кешировать похожие ответы.

Готово, когда:

- Игрок получает понятный ответ “что случилось” и “что сделать”.
- Админ видит короткую техническую сводку.

## Priority 6 - админка, модерация, роли

Статус: базовый админ-раздел есть, нужна полноценная модель полномочий.

Роли:

- `owner`: главный админ, полный доступ, владелец проекта.
- `admin`: управление пользователями, ролями, персоналом, справочниками, тикетами.
- `moderator`: проверка записей, тикеты, исправление очевидных ошибок.
- `helper`: поддержка игроков, просмотр логов/тикетов, ответы без опасных правок.
- `viewer`: просмотр разрешённых разделов.

Задачи:

- Проверить текущие Supabase permissions и RLS.
- Сделать таблицу/экран управления ролями.
- Добавить аудит действий: кто изменил роль, звание, отдел, статус тикета.
- Ограничить опасные действия только `owner`.
- Добавить защиту от удаления/понижения владельца.

Готово, когда:

- Владелец может выдать и снять роли.
- Хелпер не может менять критичные данные.
- Любое важное админ-действие видно в журнале.

## Priority 7 - лаунчер и агент live-режим

Статус: лаунчер есть, агент работает, live-режим нужно проектировать осторожно.

Задачи:

- Проверить, что агент закрывается вместе с лаунчером, если включена настройка.
- Проверить полный uninstall.
- Убрать все обрезания текста во вкладках лаунчера.
- Проверить установщик как один файл.
- Для live-режима:
  - агент периодически читает новые данные;
  - отправляет только изменения;
  - не дублирует записи;
  - показывает статус последней отправки;
  - не перегружает сайт/GitHub/шлюз.

Готово, когда:

- Игрок может включить/выключить агент из лаунчера.
- Закрытие лаунчера закрывает агент при включённой настройке.
- Live-режим обновляет сайт без дублей и без ожидания выхода из игры.
