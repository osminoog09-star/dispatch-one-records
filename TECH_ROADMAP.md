# LAPD Records technical roadmap

Цель: делать сайт, лаунчер и поддержку быстрее, но без поломки работающей системы.

## Current product

LAPD Records — тёмный MDT/records-сайт для GTA V RP:

- Flask-шаблоны в `server/app/templates`
- стили и ассеты в `server/app/static`
- статический экспорт в `docs/` для GitHub Pages
- Supabase для входа через Discord, тикетов и редакторов
- агент/лаунчер синхронизируют данные из игры

## Priority 1 — визуальный production-polish

Статус: частично сделано.

Маленькие задачи:

- Проверить все страницы на русский текст, технические даты и dev-элементы.
- Унифицировать пустые состояния: таблицы, карточки, списки.
- Привести документы ареста/суда/личного дела к одному официальному стилю.
- Проверить мобильный layout: шапка, таблицы, карта, карточки.
- Не менять Supabase JS и backend-логику.

Готовность:

- `python server/export_static.py` проходит.
- Основные страницы отдают 200.
- `rg` по `docs/` не находит явный мусор.

## Priority 2 — патрульная карта

Статус: карта есть, hover/click и статистика уже работают.

Маленькие задачи:

- Подогнать подписи и легенду так, чтобы ничего не перекрывало карту.
- Проверить сектора на desktop и mobile.
- Добавить короткие описания районов в нижнюю статистику.
- Добавить фильтр “город / округ / порт” без ломки существующего JS.
- Не добавлять воду в зоны, если это не порт/аэропорт.

Готовность:

- Hover по легенде подсвечивает сектор.
- Клик по сектору меняет информационную карточку.
- Статистика под картой не пропадает.

## Priority 3 — поддержка и диагностика логов

Статус: идея согласована, реализации нет.

Сначала сделать без AI API:

- Страница “Поддержка”.
- Поле описания проблемы.
- Загрузка `.log` / `.txt`.
- Локальный rule-based анализ известных ошибок.
- Кнопка “Создать тикет”.

Правила диагностики:

- неверный позывной, например `7 - WILIAM - 1` вместо `7-WILLIAM-1`
- `pdComp` не найден
- нет доступа к папке
- GitHub Actions usage limit
- Supabase ошибка
- webhook/token ошибка
- сеть недоступна

AI подключать вторым этапом, только после удаления секретов и ограничения размера лога.

## Priority 4 — данные и импорт

Статус: работает, трогать осторожно.

Маленькие задачи:

- Не переписывать импорт без отдельного задания.
- Если нужно исправить старые записи, делать миграцию/скрипт с dry-run.
- Не фабриковать статистику смен: если в исходных данных нули, показывать нули.
- Для связи арестов со сменами нужна отдельная логика с границами сессий.

## Priority 5 — релизы

Маленькие задачи:

- После заметного изменения сайта делать commit + push.
- Проверять GitHub Pages после обновления.
- Если Pages кэширует старую версию, сверять raw GitHub и ждать обновления Actions/Pages.

## Definition of done

Задача считается завершённой только если:

- изменены только нужные файлы;
- нет случайного редактирования `docs/` руками;
- экспорт выполнен, если менялся сайт;
- ключевые страницы открываются с 200;
- `WIP.md` и `HANDOFF.md` обновлены;
- есть понятный commit.
