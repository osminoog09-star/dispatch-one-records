# LAPD Records technical roadmap

Цель: делать сайт, лаунчер и поддержку быстрее, но без поломки работающей системы.

## Current product

LAPD Records — тёмный MDT/records-сайт для GTA V RP:

- Flask-шаблоны в `server/app/templates`
- стили и ассеты в `server/app/static`
- статический экспорт в `docs/` для GitHub Pages
- Supabase для входа через Discord, тикетов и редакторов
- агент/лаунчер синхронизируют данные из игры

## Priority 1 — визуальный production-polish

Статус: частично сделано.

Маленькие задачи:

- Проверить все страницы на русский текст, технические даты и dev-элементы.
- Унифицировать пустые состояния: таблицы, карточки, списки.
- Привести документы ареста/суда/личного дела к одному официальному стилю.
- Проверить мобильный layout: шапка, таблицы, карта, карточки.
- Не менять Supabase JS и backend-логику.

Готовность:

- `python server/export_static.py` проходит.
- Основные страницы отдают 200.
- `rg` по `docs/` не находит явный мусор.

## Priority 2 — патрульная карта

Статус: карта есть, hover/click, статистика и ссылки `?zone=...` уже работают.

Маленькие задачи:

- Подогнать подписи и легенду так, чтобы ничего не перекрывало карту.
- Проверить сектора на desktop и mobile.
- Добавить короткие описания районов в нижнюю статистику.
- Добавить фильтр “город / округ / порт” без ломки существующего JS.
- Не добавлять воду в зоны, если это не порт/аэропорт.
- Для точной точки события на карте добавить в агент/плагин запись координат `x/y`; по одному текстовому адресу сейчас можно только выбрать ближайший сектор.

Готовность:

- Hover по легенде подсвечивает сектор.
- Клик по сектору меняет информационную карточку.
- Статистика под картой не пропадает.

## Priority 3 — поддержка и диагностика логов

Статус: идея согласована, реализации нет.

Сначала сделать без AI API:

- Страница “Поддержка”.
- Поле описания проблемы.
- Загрузка `.log` / `.txt`.
- Локальный rule-based анализ известных ошибок.
- Кнопка “Создать тикет”.

Правила диагностики:

- неверный позывной, например `7 - WILIAM - 1` вместо `7-WILLIAM-1`
- `pdComp` не найден
- нет доступа к папке
- GitHub Actions usage limit
- Supabase ошибка
- webhook/token ошибка
- сеть недоступна

AI подключать вторым этапом, только после удаления секретов и ограничения размера лога.

## Priority 3.5 — администрация и полномочия

Статус: первый срез готов в исходниках, SQL нужно применить в Supabase.

Роли:

- `owner` / Главный админ: полный доступ, выдача админов, защита владельца, аудит.
- `admin` / Админ: персонал, справочники, тикеты, модерация, аудит без выдачи админов.
- `moderator` / Модератор: персонал, заявки, тикеты, аудит без справочников и ролей.
- `helper` / Хелпер: тикеты и поддержка игроков.
- `officer` / Офицер: обычный сотрудник.
- `viewer` / Наблюдатель: только просмотр.

Готово:

- Добавлена страница `/admin`.
- Навигация `Админ → Управление`.
- `supa.js` получает `my_permissions()` и выставляет `window.lapd.canTickets`, `canStaff`, `canDictionaries`, `canAdmins`.
- Тикеты доступны хелперам/модераторам/админам.
- Редактор персонала доступен ролям с `can_staff`.
- Справочники доступны ролям с `can_dictionaries`.
- Добавлена миграция `supabase/admin_roles.sql`.

Что сделать владельцу в Supabase:

- Один раз применить `supabase/admin_roles.sql`.
- После входа через Discord назначить себе `owner` командой из конца файла.
- Проверить, что `/admin` показывает роль “Главный админ”.

## Priority 4 — данные и импорт

Статус: работает, но есть важные доработки по сменам и live-режиму.

Уже сделано:

- Главная показывает статистику за 24 часа, 7 дней и 30 дней.
- Главная показывает расширенную сводку базы по всему, что реально можно достать из текущих таблиц: аресты, уникальные фигуранты, штрафы, суды, вызовы, предупреждения, транспорт, изъятое.
- Страница смен показывает сводку за 24 часа, 7 дней и 30 дней.
- `/api/shift` после сохранения смены пробует отправить Discord-рапорт через `DISCORD_WEBHOOK_SHIFTS` или общий webhook.
- Агент добавляет в сменный рапорт поля `callouts`, `pursuits`, `pit`; пока вызовы считаются как новые аресты за сессию, потому что полноценного отдельного журнала вызовов pdComp не отдаёт.
- В `AUTO_PUBLISH=1` агент публикует изменения во время игры с интервалом `LIVE_PUBLISH_SECONDS` (по умолчанию 90 секунд, минимум 30). Это близко к live для GitHub Pages, но не заменяет настоящий realtime backend.

Маленькие задачи:

- Не переписывать импорт без отдельного задания.
- Если нужно исправить старые записи, делать миграцию/скрипт с dry-run.
- Не фабриковать статистику смен: если в исходных данных нули, показывать нули.
- Для связи арестов со сменами нужна отдельная логика с границами сессий.
- Пересобрать и выпустить новый `pdcomp_sync.exe`, иначе игроки со старым агентом не получат новые поля смены.
- После изменения live-режима тоже нужен новый `pdcomp_sync.exe`, иначе игроки/владелец продолжат ждать публикацию до выхода из игры.
- Проверить, что в GitHub Actions/локальном запуске заданы `DISCORD_WEBHOOK_SHIFTS` или `DISCORD_WEBHOOK_URL`.
- Если нужен настоящий журнал вызовов без привязки к аресту, нужен отдельный источник от игрового плагина/агента.
- Для точных “эвакуаций”, “застрелено”, “ранено” нужны отдельные поля от агента/плагина. Сейчас такие события можно считать только как текстовые упоминания в описании/статьях.

## Priority 5 — релизы

Статус: onedir-релиз лаунчера сделан в `1.4.11`; `launcher_url` указывает на zip-архив.

Маленькие задачи:

- После заметного изменения сайта делать commit + push.
- Проверять GitHub Pages после обновления.
- Если Pages кэширует старую версию, сверять raw GitHub и ждать обновления Actions/Pages.
- После изменения `launcher/launcher.py` пересобрать `launcher/dist/LAPD-Records-Launcher.exe` и проверить, что в комплект попали `pdcomp_sync.exe`, `DispatchOne.MDT.dll` и нужные изображения баннера.
- Не считать изменение лаунчера доставленным игрокам, пока не обновлён exe/manifest.
- ВАЖНО (баг у игроков): ошибка `Failed to load Python DLL '…\_MEI…\python314.dll' … LoadLibrary: Не найден указанный модуль` лечится только пересборкой в `--onedir` (без `--onefile`). В onefile PyInstaller распаковывает `python314.dll` во временную `_MEI…`, антивирус/очистка temp её сносит → лаунчер не стартует. onedir кладёт DLL рядом с exe, в temp ничего не распаковывается. Детали и полный бриф переделки лаунчера: `launcher/REDESIGN_BRIEF.md`; распределение работ Claude↔Codex: `ROADMAP_TEAM.md`.

## Definition of done

Задача считается завершённой только если:

- изменены только нужные файлы;
- нет случайного редактирования `docs/` руками;
- экспорт выполнен, если менялся сайт;
- ключевые страницы открываются с 200;
- `WIP.md` и `HANDOFF.md` обновлены;
- есть понятный commit.
