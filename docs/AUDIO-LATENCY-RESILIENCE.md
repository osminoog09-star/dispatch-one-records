# Аудио-тракт, бюджет задержки, устойчивость и контроль расхода

**Назначение:** технические детали, от которых realtime-голос живёт или умирает.

---

## 1. Аудио-тракт (форматы и ресемплинг)

```
ВХОД (микрофон → Gemini):
  NAudio WASAPI → PCM16 моно 16кГц (Gemini требует ровно это).
  Микрофон часто 44.1/48кГц → РЕСЕМПЛ до 16кГц на клиенте.
  Чанки ~20-40 мс, base64 → realtimeInput (BACKEND-SPEC §4.3).

ВЫХОД (Gemini → игра):
  Gemini отдаёт PCM ~24кГц. Проигрывать через NAudio.
  При несовпадении с устройством — ресемпл до 44.1/48кГц.

Edge-TTS (если используем): отдаёт обычно 24кГц mp3/opus → декод + ресемпл.
```

**Эхо/фидбек:** голос диспетчера НЕ должен попадать обратно в микрофон.
```
- PTT решает базово: микрофон открыт только когда зажата клавиша.
- Если игрок говорит одновременно с ответом — это норм для рации (полудуплекс).
- Не выводить голос диспетчера на то же устройство, что слушает микрофон в open-mic
  (в PTT-режиме не проблема).
```

## 2. Бюджет задержки (latency budget)

Цель: первый звук ответа ≤ ~1.5 сек после отпускания PTT (для рации терпимо, там паузы норм).

```
Захват + ресемпл на клиенте        ~20-50 мс
Клиент → бэкенд (localhost/близко) ~5-30 мс
Бэкенд → Gemini (регион)           ~30-120 мс
Gemini обработка (thinkingBudget:0)~300-800 мс  ← основное
Gemini → бэкенд → клиент           ~40-150 мс
Буфер проигрывания                 ~50-100 мс
                                   ─────────────
ИТОГО первый звук                  ~0.5-1.3 сек (реально)
```

**Рычаги:**
```
- thinkingBudget:0 (обязательно) — без «раздумий».
- Бэкенд ближе к региону Gemini (не гонять через полмира).
- Стримить выход по мере поступления (не ждать всю реплику).
- Короткий системный промпт для холодного старта? Нет — он ставится один раз на сессию,
  на пореплику не влияет. Держим полный.
- maxOutputTokens умеренный (512) — короткие реплики = быстрее.
```

## 3. Устойчивость (resilience matrix)

| Сбой | Поведение |
|---|---|
| Обрыв WS до Gemini | Реконнект + восстановление сессии по `sessionResumption` (BACKEND-SPEC §4.2). Клиенту `error`, но игра не падает. |
| Rate-limit free-tier (см. §4) | Бэкенд ловит 429 → сообщение «диспетчер временно недоступен», бэкофф, лог. НЕ спамить ретраями. |
| Ключ исчерпан/невалиден | Явная ошибка в лог + клиенту, не молчаливый провал. |
| Микрофон отключён | Клиент детектит, лог, не крашит игру. |
| Игра/плагин упал | Бэкенд закрывает сессию по таймауту, освобождает ресурсы. |
| Бэкенд недоступен | Клиент: несколько ретраев с бэкоффом, потом «диспетчер офлайн», без краша. |
| Долгая тишина | Таймаут сессии (напр. 15 мин) → закрыть, освободить квоту. |

## 4. Лимиты free-tier (упрутся СРАЗУ на тестах!)

```
Gemini free-tier (AI Studio):
  - Есть суточные/минутные лимиты запросов (RPM/RPD) и лимиты токенов.
  - Live API на free-tier может быть ограничен сильнее обычного — ПРОВЕРИТЬ реальный
    лимит перед вехой 4, чтобы тесты не встали.
  - Стратегия: короткие тестовые сессии, кап минут, следить за 429.

План на случай упора в лимит:
  - Держать 2-3 ключа для тестов (ротация в пуле — как конкурент `vinewood-pool`).
  - Edge-TTS убирает выходной звук из Gemini → меньше нагрузка на квоту.
  - При переходе к реальному использованию — платный ключ (но это уже не $0).
```

## 5. Защита ключа и анти-абьюз (когда пойдёт к людям)

```
Проблема: если наш бэкенд проксирует наш ключ Gemini многим — кто-то может выжрать квоту/деньги.

Меры:
  - Авторизация клиентов (токены), без токена — отказ.
  - Rate-limit НА ПОЛЬЗОВАТЕЛЯ (минуты/сессии в сутки).
  - Кап минут по тарифу (см. BUSINESS-STRATEGY).
  - Ключ Gemini только на сервере, НИКОГДА в клиентском .ini (в отличие от «BYO-key»,
    где юзер осознанно ставит свой).
  - Логирование потребления по юзеру для детекта аномалий.
  - «BYO-key» тариф вообще снимает этот риск (юзер на своём ключе).
```

## 6. Наблюдаемость (что логировать для отладки AI)

```
- Транскрипты вход/выход (inputAudioTranscription/output) — понимать, что услышал/сказал.
- Распознанные токены команд + исполнение (успех/ошибка).
- Задержки по этапам (для бюджета §2).
- 429/ошибки Gemini, реконнекты.
- Потребление минут/токенов на сессию (для экономики).
Хранить локально в dev; на проде — с учётом приватности (не светить голос без нужды).
```
