# Карьерный мод — полный дизайн

**Модуль проекта Dispatch One.** Полноценная карьера офицера для LSPDFR, интегрированная с AI-диспетчером.
**Статус:** дизайн на бумаге.

---

## 1. Позиционирование и границы

**Конкурент:** `LSPDFR Enhanced: Remastered` — зрелый мод: карьера, ранги, XP, смены с задачами, зарплата, отчёты + огромный лайфстайл-слой (голод, усталость, одежда, квартиры, гараж, магазины, автосалон).

**Наш подход — НЕ клонировать его целиком.**

```
В ОБЪЁМЕ (делаем глубоко):
  ✔ Карьера: звания, повышения, XP, стаж (дни/смены/часы)
  ✔ Смены: типы (день/вечер/ночь), задачи, начало/конец, отчёт по смене
  ✔ Статистика: вызовы, аресты, остановки, погони, штрафы
  ✔ Разблокировки: участки, зоны патрулирования, назначения
  ✔ Зарплата/бюджет (лёгкий, как следствие карьеры)

ВНЕ ОБЪЁМА (не наша война):
  ✘ Лайфстайл-сим: голод, усталость, готовка, одежда, квартиры, магазины, автосалон
    → это ядро Enhanced, огромный объём и не наше отличие
```

**Наш клин:** карьера **× AI-диспетчер**. Ни у Enhanced нет живого AI-голоса, ни у AI-диспетчеров нет карьеры. Связка — уникальна (см. §7).

## 2. Ключевые сущности

```
OfficerProfile     — профиль офицера (несколько профилей на игрока)
  id, name, agency (LSPD/BCSO/SAHP), createdAt

CareerState        — состояние карьеры профиля
  rank, xp, totalShifts, daysWorked, hoursOnDuty, salary, unlocks[]

Shift              — одна смена (= один выход на службу)
  id, number, type (day|swing|night), startedAt, endedAt, durationMin,
  objectives[], stats (см. §5), xpEarned, report

CareerRecords      — накопительная статистика за всю карьеру
  callouts, arrests, stops, pursuits, citations, incidents
```

## 3. Система смен

### 3.1. Типы смен
| Тип | Игровое время | Характер |
|---|---|---|
| **Дневная** (day) | 06:00-14:00 | Плотный трафик, много остановок, мелкие вызовы |
| **Вечерняя** (swing) | 14:00-22:00 | Пик активности, драки, ДТП |
| **Ночная** (night) | 22:00-06:00 | Меньше вызовов, но тяжелее: DUI, ограбления, погони |

Тип влияет на: набор задач смены, множитель XP, **тон и плотность эфира диспетчера** (§7).

### 3.2. Жизненный цикл смены
```
1. Выход на службу (OnOnDutyStateChanged=true)
   → определяем тип смены по игровому времени
   → выдаём задачи смены (2-4 штуки)
   → диспетчер приветствует с учётом карьеры («Смена сорок семь, ночная, сержант»)

2. В процессе — polling-движок пишет события (§6.1)

3. Конец смены (OnOnDutyStateChanged=false)
   → считаем статистику, XP, зарплату
   → проверяем повышение
   → показываем ОТЧЁТ ПО СМЕНЕ
   → сохраняем в профиль
```

### 3.3. Задачи смены (objectives)
Примеры (генерируются под тип смены):
```
- Обработать 3 вызова                    (+XP)
- Провести 5 остановок транспорта         (+XP)
- Завершить смену без жалоб               (+бонус)
- Патрулировать назначенную зону ≥30 мин  (+XP)
- Произвести арест                        (+XP)
```

### 3.4. Отчёт по смене
```
СМЕНА №47 · НОЧНАЯ · 22:14 — 04:38 (6ч 24м)
─────────────────────────────────────────
Вызовов обработано:      4
Остановок:               7
Арестов:                 2
Погонь:                  1 (успешная)
Штрафов выписано:        3
Задачи:                  3/4 выполнено
─────────────────────────────────────────
XP за смену:            +340
Зарплата:               $520
Прогресс до звания «Сержант II»:  1840/2500
```

## 4. Прогрессия

### 4.1. Звания (пример лестницы, настраивается)
```
Cadet → Officer I → Officer II → Officer III →
Senior Officer → Corporal → Sergeant I → Sergeant II →
Lieutenant → Captain
```
Для BCSO/SAHP — свои лестницы (Deputy → Senior Deputy → ... / Trooper → ...).

### 4.2. Источники XP
| Действие | XP |
|---|---|
| Завершённый вызов | 50-150 (по типу) |
| Остановка транспорта | 15 |
| Арест | 60 |
| Успешная погоня | 100 |
| Задача смены | 50-100 |
| Полная смена без инцидентов | бонус ×1.2 |
| **Штрафы:** жалоба / ранение гражданского / провал вызова | −XP |

### 4.3. Разблокировки по званию
Опираемся на **реальные данные LSPDFR** (файлы на диске):
```
data/stations.xml   → участки (разблокировка новых мест выхода на смену)
data/regions.xml    → зоны патрулирования
data/agency.xml     → агентства
data/outfits.xml    → форма (косметика по званию)
backup.xml          → типы доступного подкрепления
```
Пример: Sergeant → доступ к участку Vespucci + зона Vinewood + запрос SWAT.

## 5. Что трекаем и откуда берём данные

| Метрика | Источник | Как |
|---|---|---|
| Начало/конец смены | `Functions.OnOnDutyStateChanged` | **Событие** (единственное надёжное) |
| Выбор дежурства | `Functions.PlayerWentOnDutyFinishedSelection` | Событие |
| Агентство | `Functions.GetCurrentAgencyScriptName()` | Запрос |
| Зона/район | `Functions.GetZoneAtPosition(pos)` → `.RealAreaName`, `.County` | Запрос (poll) |
| Вызов идёт/завершён | `IsCalloutRunning()`, `GetCurrentCallout()`, `GetCalloutFriendlyName()` | **Poll + edge** |
| Погоня | `GetActivePursuit()`, `IsPursuitStillRunning()` | **Poll + edge** |
| Арест | `IsPlayerArresting()`, `IsPedArrested(ped)`, `GetPedArrestingOfficer(ped)` | **Poll + edge** |
| Остановка | `IsPedStoppedByPlayer(ped)`, `GetPulloverSuspect(pullover)` | **Poll + edge** |
| Обыск | `IsPedBeingFriskedByPlayer(ped)`, `HasPedBeenFrisked(ped)` | Poll |
| Штрафы / история лица | `Persona.Citations`, `Persona.TimesStopped`, `Persona.Wanted` | Запрос |

> **КРИТИЧНО:** у LSPDFR всего **два события**. Всё остальное — только методы-запросы.
> Значит нужен **polling-движок с детекцией фронтов** (было→стало). Именно так делает
> и диспетчер Vinewood (`PollLoop`, `_wasInPursuit`, `_wasInCallout`).

### 5.1. Опциональные источники (через рефлексию, если мод стоит)
```
CalloutInterface     → надёжные данные о завершении вызовов из РАЗНЫХ паков
PolicingRedefined    → аресты/процедуры/отчёты
CommonDataFramework  → расширенные данные лиц и машин
GrammarPolice        → статусы 10-8/10-7
LSPDFR Enhanced      → если стоит: синхронизация, не дублировать карьеру (§8)
```

## 6. Техническая архитектура

```
clients/lspdfr-career/           (C# .NET Framework 4.8, плагин RPH)
  EntryPoint.cs            — Plugin: Initialize/Finally, подписка на 2 события
  Core/
    PollEngine.cs          — тик (напр. 1-2 Гц), детекция фронтов (§6.1)
    ShiftManager.cs        — жизненный цикл смены, задачи, отчёт
    CareerManager.cs       — XP, звания, повышения, разблокировки
    Records.cs             — накопительная статистика
  Data/
    ProfileStore.cs        — сохранение/загрузка профилей (JSON)
    RankTable.cs           — лестницы званий по агентствам (из конфига)
  Integration/
    ModBridge.cs           — рефлексия к чужим модам (§5.1), всё опционально
    DispatchBridge.cs      — отдача карьеры в Dispatch One (§7)
  UI/
    CareerMenu.cs          — меню карьеры (RAGENativeUI — есть на диске)
    ShiftReportScreen.cs   — экран отчёта по смене
  Career.ini
```

### 6.1. Polling-движок (ядро)
```
Тик 1-2 раза в секунду. Для каждой отслеживаемой величины храним прошлое значение
и ловим ПЕРЕХОД:

  wasInPursuit=false → GetActivePursuit()!=null   ⇒ событие PursuitStarted
  wasInCallout=true  → IsCalloutRunning()==false  ⇒ событие CalloutCompleted
  wasArresting=false → IsPlayerArresting()==true  ⇒ событие ArrestMade
  wasStopped=false   → IsPedStoppedByPlayer()     ⇒ событие TrafficStop

Каждое событие → в текущую Shift.stats + в очередь для диспетчера.
Тик держать лёгким (не дёргать тяжёлые API каждый кадр).
```

### 6.2. Персистентность
```
%APPDATA%\DispatchOne\career\profiles\<profileId>.json

{
  "profile": { "id","name","agency","createdAt" },
  "career":  { "rank","xp","totalShifts","daysWorked","hoursOnDuty","unlocks":[] },
  "records": { "callouts","arrests","stops","pursuits","citations" },
  "shifts":  [ { "number","type","startedAt","durationMin","stats","xpEarned" } ]
}
```
Автосейв в конце смены + периодически (защита от краша игры).

## 7. Интеграция с AI-диспетчером (наш клин)

Карьера отдаёт диспетчеру контекст — тот озвучивает и учитывает.

```
CareerContext → в GameContext / ShiftMemory диспетчера:
{
  "rank": "Сержант",
  "shift_number": 47,
  "shift_type": "night",
  "days_worked": 31,
  "career_stats": { "arrests": 128, "pursuits": 42 },
  "recent_promotion": true
}
```

**Что это даёт в эфире (чего нет ни у кого):**
```
- «Смена сорок семь, ночная. Доброе утро, сержант.»
- «Поздравляю с повышением» — при апе звания.
- Ночная смена → эфир реже, тон спокойнее; дневная → плотнее.
- «У тебя это третий арест за смену» — статистика в реплике.
- Задачи смены озвучиваются диспетчером как наряд, а не всплывашкой.
```

> Технически: карьерный модуль шлёт `context`-апдейт в бэкенд Dispatch One тем же
> каналом `clientContent` (BACKEND-SPEC §4.5). Диспетчер вставляет это в промпт.

## 8. Совместимость с другими модами (главное требование)

```
ПРИНЦИП: ничего не ломаем, ни с кем не воюем, всё чужое — опционально через рефлексию.

1. Не перехватываем и не переопределяем чужие системы. Только ЧИТАЕМ состояние.
2. Все интеграции — try/catch + проверка «загружен ли мод». Нет мода → работаем без него.
3. Свои сохранения в своей папке (%APPDATA%\DispatchOne), не трогаем чужие файлы.
4. Не подменяем LSPDFR stats.dat и прочие игровые данные — только читаем.
5. Если стоит LSPDFR Enhanced:
   → режим «не дублировать»: не ведём свою карьеру параллельно,
     а ЧИТАЕМ его звание/смену и отдаём диспетчеру (§7).
   → пользователь выбирает в Career.ini: standalone | bridge | off
6. Polling-тик лёгкий, чтобы не просаживать FPS рядом с тяжёлыми модами.
```

## 10. Вехи разработки

```
1. Каркас плагина + подписка на 2 события + профиль (создание/сохранение).
2. ShiftManager: начало/конец смены, длительность, счётчик смен и дней.
3. PollEngine: детекция вызовов/погонь/арестов/остановок → статистика смены.
4. Отчёт по смене (экран) + сохранение истории.
5. CareerManager: XP, лестница званий, повышения.
6. Задачи смены (генерация под тип смены) + бонусы.
7. Разблокировки (участки/зоны из stations.xml, regions.xml).
8. UI-меню карьеры (RAGENativeUI).
9. DispatchBridge → интеграция с AI-диспетчером (§7).
10. Режим bridge с LSPDFR Enhanced (§8.5).
```

## 11. Риски

| Риск | Митигация |
|---|---|
| **Конкуренция с LSPDFR Enhanced** (зрелый, огромный) | Не клонируем лайфстайл; наш клин — связка с AI-диспетчером; режим bridge вместо войны. |
| Нет событий в LSPDFR → polling | Лёгкий тик 1-2 Гц, детекция фронтов, не дёргать тяжёлые API часто. |
| Просадка FPS от polling | Профилировать; тик настраиваемый; тяжёлые запросы реже. |
| Ложные срабатывания детекции (арест/остановка) | Дебаунс + подтверждение по нескольким тикам. |
| Конфликты сохранений с другими модами | Своя папка, только чтение чужого. |
| Объём работы | Вехи 1-5 = играбельное ядро; 6-10 — наращивание. |
```

## 12. Приложение: точные факты из рефлексии (для кода)

**Единственные два события LSPDFR** (подтверждено Mono.Cecil по `LSPD First Response.dll`):
```
Functions.OnOnDutyStateChanged(bool onDuty)
Functions.PlayerWentOnDutyFinishedSelection()
```
Всё остальное (аресты/остановки/погони/вызовы) — методы-запросы → polling (§6.1).

**Точные script-имена агентств** (из `duty_selection.xml`) — для лестниц званий по агентству (§4.1):
```
lspd, lspd_swat   — полиция города (+ SWAT)
lssd, lssd_swat   — шериф округа (BCSO) (+ SWAT)
sahp, sasp        — дорожная / гос. патруль (трассы)
fib               — федералы
```
`Functions.GetCurrentAgencyScriptName()` вернёт одно из этих.

**Почтовый индекс** (нужен и карьере, и диспетчеру) — НЕ в ядре LSPDFR:
```
CalloutInterface.Functions.GetPostalCode(Vector3 pos)   ← брать отсюда (через рефлексию)
```
`CalloutInterface.dll` уже установлен. Его же `Functions.GetCalloutFromHandle` полезен для
надёжного детекта вызовов из разных паков.

**Ключевые методы трекинга** (сигнатуры проверены):
```
IsPlayerArresting() : bool
IsPedArrested(Ped) : bool ; GetPedArrestingOfficer(Ped) : Ped
IsPedStoppedByPlayer(Ped) : bool ; GetPulloverSuspect(LHandle) : Ped
GetActivePursuit() : LHandle ; IsPursuitStillRunning(LHandle) : bool
IsCalloutRunning() : bool ; GetCurrentCallout() : LHandle ; GetCalloutFriendlyName(LHandle) : string
HasPedBeenFrisked(Ped) : bool
```
