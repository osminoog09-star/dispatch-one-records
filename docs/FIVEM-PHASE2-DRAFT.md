# FiveM — черновик Фазы 2

**Назначение:** архитектура фронта для FiveM (мультиплеер). Мозг — тот же бэкенд.
**Статус:** черновик. Уточнить фреймворк сервера (ESX / QBCore / кастом) до реализации.

---

## 1. Ключевое отличие от LSPDFR

| | LSPDFR (Фаза 1) | FiveM (Фаза 2) |
|---|---|---|
| Тип | одиночка | мультиплеер, клиент-сервер |
| API | RagePluginHook / LSPDFR `Functions` | CitizenFX-нативы, серверные события |
| Полиция | LSPDFR | фреймворк: ESX / QBCore / qb-policejob / кастом CAD |
| Язык ресурса | C# (.NET Framework) | Lua / JS / C# (CitizenFX) |
| Голос диспетчера | локальный WAV одному игроку | **в войс-канал для всех рядом** (pma-voice/mumble) |

Мозг (бэкенд) **переиспользуется целиком**. Пишем заново только «переходник» к игре.

---

## 2. Архитектура

```
FiveM сервер
  ├─ resource: ai-dispatcher (наш)
  │    server.lua  — события полиции (вызовы, статусы) → бэкенд; приём команд
  │    client.lua  — PTT игрока, захват голоса, проигрывание ответа в войс-канал
  │
  ├─ pma-voice / mumble-voip — войс-инфраструктура (голос диспетчера вливаем сюда)
  └─ framework (ESX/QBCore) — job=police, вызовы, MDT/CAD

        │ WebSocket/HTTP
        ▼
   Бэкенд-«мозг» (тот же, что в Фазе 1) — на хостинге (тут уже нужен, т.к. игроки удалённо)
```

---

## 3. Открытые технические вопросы

1. **Фреймворк** — ESX / QBCore / кастом? Определяет, как читать job=police, вызовы,
   MDT-пробивы. (Блокер Фазы 2.)
2. **Войс-инъекция** — как влить голос диспетчера в pma-voice так, чтобы слышали все
   рядом/на канале рации, а не один клиент. Варианты: серверный войс-бот в канале,
   или проигрывание через NUI + пространственный звук. Нужен прототип.
3. **PTT и захват голоса** — FiveM имеет свой войс; берём микрофон через NUI/встроенное
   или параллельным каналом. Уточнить.
4. **Мультиигрок** — один диспетчер на сервер обслуживает много копов: очередь реплик,
   позывные разных игроков, приоритеты (11-99 вперёд). Логика в бэкенде (ShiftMemory
   становится «памятью смены сервера»).
5. **Хостинг** — тут облако/сервер обязателен (игроки удалённые). Экономика — см.
   основной анализ: облако pay-per-use на старте, свой GPU при стабильной нагрузке.

## 6. Порядок (когда дойдём)

```
1. Уточнить фреймворк сервера.
2. Прототип войс-инъекции в pma-voice (самый рискованный кусок — проверить первым).
3. Ресурс: PTT игрока → бэкенд → голос в канал.
4. Интеграция вызовов/статусов фреймворка → GameContext.
5. Мультиигрок: очередь реплик, приоритеты.
6. Тест с коллективом на своём сервере (полигон), потом — продукт для чужих серверов.
```
