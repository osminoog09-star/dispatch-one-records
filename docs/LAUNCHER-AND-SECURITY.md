# Лаунчер Dispatch One + модель защиты

**Назначение:** дизайн нашего лаунчера и защита продукта от реверса/пиратства — чтобы с нами
не случилось то, что я сделал с Vinewood за один вечер.
**Статус:** дизайн на бумаге.

---

## 0. Главный принцип (читать первым)

**Клиентский код нельзя защитить на 100%.** Всё, что исполняется у пользователя, вскрывается —
обфускация лишь удорожает реверс, не отменяет его. Я вскрыл Vinewood НЕ потому что они плохо
обфусцировали, а потому что **они положили ценное (промпт, ключ) в клиент.**

> ЕДИНСТВЕННАЯ настоящая защита: **ценность держим на сервере, клиент делаем «глупым».**

У нас это уже так: мозг (промпт, логика, LLM) на бэкенде. Клиент только ловит микрофон,
шлёт состояние, играет звук. Укради/декомпилируй наш клиент — без нашего сервера он пустой.

## 1. Что я вскрыл у Vinewood — и уроки

| Их ошибка | Что дала | Наш урок |
|---|---|---|
| Главный DLL `Vinewood.AIDispatch` — **без обфускации** | Прочитал весь код, все 36 команд | Клиент обфусцировать, но не полагаться на это |
| **60К-промпт лежал в клиенте** (system instruction) | Достал их главный актив | Промпт — ТОЛЬКО на сервере, никогда в клиенте |
| **API-ключ в открытом `.ini`** | Готовый ключ Google | Ключи — только на сервере, клиент ходит по токену |
| `license.lic` — **открытый JSON** | Видна структура лицензии | Лицензия валидируется сервером, локально — зашифровано |
| Лаунчер — **Electron `app.asar`** | Вся JS-логика распаковывается | Tauri (нативный Rust) вместо Electron; логика на сервере |
| `vh_dispatch` — ConfuserEx, но **строки утекли** | Достал модель, TTS-промпт | Если обфускация — то с ПРАВИЛЬНЫМ шифрованием строк |
| `auth.token` — **DPAPI/safeStorage** ✅ | Не смог прочитать | Единственное, что переняли: так и храним токены |

## 2. Модель «где что живёт» (секрет → место)

| Актив | Где ХРАНИТСЯ | Почему |
|---|---|---|
| **Системный промпт диспетчера** | 🖥️ Только сервер | Главный IP. В клиент не попадает никогда. |
| **LLM-логика, парсинг команд, память смены** | 🖥️ Сервер | Ценность — на бэкенде. |
| **API-ключи (Gemini/Edge-TTS)** | 🖥️ Сервер | Клиент их не видит. Ходит по нашему токену. |
| **Проверка лицензии/подписки** | 🖥️ Сервер | Клиент не решает «пускать ли» — решает сервер. |
| Транспорт аудио, интеграция с игрой | 💻 Клиент | Мало ценности; можно обфусцировать. |
| Токен сессии/авторизации | 💻 Клиент, **зашифрован DPAPI** | Как у Vinewood (единственное, что у них верно). |
| Настройки пользователя | 💻 Клиент, открыто | Не секрет. |

Правило: **если это ценно или это ключ — оно на сервере.** Точка.

## 3. Слои защиты (от важного к второстепенному)

### A. Архитектурная (самая важная, уже есть)
```
Клиент бесполезен без сервера. Промпт, логика, ключи, LLM — серверные.
Реверс клиента даёт только «как он шлёт аудио», а не «как работает диспетчер».
```

### B. Аутентификация и лицензирование (серверные)
```
- Вход → сервер выдаёт короткоживущий JWT-токен (истекает, обновляется).
- Каждый запрос к мозгу проверяется на сервере: валиден ли токен, активна ли подписка.
- HWID-привязка: токен привязан к отпечатку железа → не расшарить одну лицензию на всех.
- Rate-limit на пользователя (минуты/сессии) — против абьюза и слива ключа.
- Отзыв: скомпрометированную лицензию гасим на сервере мгновенно.
→ Взлом клиента бесполезен: сервер всё равно не пустит без валидной серверной проверки.
```

### C. Хранение секретов на клиенте
```
- Токены — через Windows DPAPI / Electron safeStorage / Tauri stronghold (привязка к юзеру ОС).
- НИКОГДА: ключи, промпт, лицензию в открытом .ini/.json (ошибка Vinewood).
- Лицензия локально (если кэшируем) — зашифрована + подписана сервером (проверка подписи).
```

### D. Обфускация клиентского кода (замедляет, не останавливает — честно)
```
LSPDFR-плагин (.NET):
  - ConfuserEx (бесплатно), НО с правильными пресетами: control-flow + ПОЛНОЕ шифрование
    строк + anti-tamper + anti-debug. (У Vinewood строки утекали — не повторять.)
  - Сильнее (платно): .NET Reactor / Eazfuscator — если бюджет позволит.
  - Всё чувствительное всё равно НЕ в плагине (см. §2).

Лаунчер:
  - Tauri (Rust) вместо Electron: бэкенд компилится в нативный бинарь (реверсить труднее,
    чем JS-asar). Фронт — web, но без ценной логики.
  - Если всё же Electron: bytenode (V8-байткод) + asar integrity, но это слабее Tauri.
```

### E. Целостность и anti-tamper
```
- Сервер проверяет версию/подпись клиента при подключении (старый/модифицированный — отказ).
- Подписанные сборки; детект модификации DLL.
- Опц.: контрольные суммы клиента, сверяемые сервером.
```

### F. Бизнес-логика — на сервер, сколько можно
```
Всё, что определяет ЦЕННОСТЬ и ПРАВА (что за подписку доступно, лимиты, промпт, модели),
считается на сервере. Клиент — исполнитель, не источник правды.
```

## 4. Дизайн лаунчера Dispatch One

### 4.1. Назначение
```
- Установка/обновление НАШЕГО плагина (диспетчер + карьера) в plugins\LSPDFR.
- Вход в аккаунт, показ статуса подписки/лицензии.
- Помощь с зависимостями: список нужных модов со ССЫЛКАМИ на официальные источники
  (не раздаём чужое — см. LEGAL-IP).
- Запуск игры через RagePluginHook.
- Настройки: устройство микрофона, PTT, режим мозга (облако/локальный/BYO-key), язык.
- Дельта-обновления нашего плагина.
```

### 4.2. Стек — рекомендация: **Tauri** (не Electron)
```
Почему Tauri:
  + Бэкенд на Rust → нативный бинарь, реверс сложнее, чем JS-asar (который я распаковал у них).
  + Легче и меньше (нет полного Chromium в комплекте).
  + Секреты/логику держит в Rust-части, не в открытом фронте.
  - Меньше готовых примеров, чем у Electron (но для нашей задачи хватает).

Electron допустим для скорости старта, но тогда: bytenode + asar integrity + НИКАКИХ
секретов во фронте.
```

### 4.3. Структура
```
launcher/                        (Tauri)
  src-tauri/                     — Rust: сеть, установка, DPAPI-хранилище токена, запуск игры
    auth.rs                      — вход, хранение токена (stronghold/DPAPI)
    installer.rs                 — установка/обновление плагина, проверка целостности
    game_launch.rs               — запуск RPH
  src/                           — фронт (web): UI, без ценной логики
  updater/                       — дельта-апдейты нашего плагина (подписанные)
```

### 4.4. Что лаунчер НЕ делает
```
✘ Не хранит API-ключи (они на сервере).
✘ Не содержит промпт/логику диспетчера.
✘ Не раздаёт чужие моды (только ссылки).
✘ Не решает сам «активна ли подписка» — спрашивает сервер.
```

## 5. Поток лицензии/подписки (безопасный)

```
1. Пользователь входит в лаунчере → сервер проверяет подписку → выдаёт JWT (короткий срок) + HWID-привязка.
2. Токен хранится зашифрованным (DPAPI).
3. Плагин при старте берёт токен у лаунчера/из хранилища → шлёт на наш бэкенд.
4. Бэкенд на КАЖДЫЙ запрос проверяет: токен валиден? подписка активна? лимит не превышен? HWID совпал?
5. Нет/просрочен/отозван → мозг не отвечает. Клиент сам ничего не «разрешает».
6. Токен протухает → тихое обновление через сервер.
```
Даже полностью взломанный клиент не даёт доступа к мозгу без валидной серверной проверки.

## 6. Честные пределы (чтобы не строить иллюзий)

```
- Локальный/BYO-key тариф: если пользователь на СВОём ключе и/или локальной модели,
  то логика у него на машине → защитить нечего. Это осознанный выбор тарифа (открытость).
  Ценность (наш промпт) всё равно можно держать серверно даже в этом тарифе (клиент тянет
  промпт с сервера под токеном, не хранит локально).
- Обфускация .NET вскрывается (я почти вскрыл ConfuserEx). Не полагаться на неё как на главное.
- Пиратство клиента возможно, но БЕСПОЛЕЗНО без нашего сервера — в этом вся суть модели.
```
