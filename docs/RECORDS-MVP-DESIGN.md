# Records MVP — статистика дел в Discord + сайт (дополнение к Vinewood)

**Фокус (2026-07-22):** самостоятельный проект — мод собирает дела/статистику и шлёт в Discord
+ на свой сайт. **Работает ВМЕСТЕ с Vinewood** (не конкурент, не трогает диспетчер/микрофон).
Диспетчер/карьера-конкурент/лаунчер/FiveM — отложены в отдельный проект.

---

## 1. Позиционирование

```
НЕ конкурент Vinewood. Надстройка сверху:
  - Vinewood даёт AI-диспетчера (голос) — не трогаем.
  - Наш мод ЧИТАЕТ данные LSPDFR (аресты, дела) и постит наружу.
  - Оба работают параллельно, конфликта нет (мы не слушаем микрофон, не спавним подкрепление).
```

## 2. Принятый MVP-скоуп (по решениям)

```
✔ Заполнение — ПОЛНОСТЬЮ АВТОМАТ: мод сам берёт то, что даёт игра. Без ручных форм.
✔ Формат дела — И скрин игры (фото сцены) И красивая карточка из данных (кириллица работает).
✔ Сайт — под ОДНО сообщество (LAPD) на старте. Мульти-тенант — позже.
```

## 3. Три компонента

```
① Мод (C# LSPDFR-плагин)   — детект ареста → сбор данных + скриншот → отправка в API.
② API + БД (наш сервер)     — принимает, хранит, постит в Discord.
③ Сайт (веб-дашборд)        — профили офицеров, реестр дел, статусы, статистика.
```

## 4. Поток данных

```
Игрок арестовал (в игре, рядом с Vinewood)
   │  мод детектит (poll LSPDFR: IsPedArrested / IsPlayerArresting — как в карьерном модуле)
   │  собирает АВТО-данные + делает скриншот
   ▼
[наш API]  POST /case
   ├─►  БД: создать «дело»
   └─►  Discord webhook: embed-карточка + прикреплённый скрин
   ▼
Сайт: дело появилось у офицера (профиль, реестр, статус «Подано»)
```

## 5. Что мод собирает АВТОМАТОМ (без ручного ввода)

Из игры (LSPDFR API + Persona задержанного):
```
- Подозреваемый: Persona.FullName, Gender, Birthday
- Статус: Wanted (в розыске), ELicenseState (права: Valid/Suspended/Expired), Citations
- Где: район GetZoneAtPosition().RealAreaName + индекс CalloutInterface.GetPostalCode
- Когда: игровое время + реальная метка
- Офицер: позывной (7-WILLIAM-1, из GrammarPolice custom.ini) + имя
- Скриншот сцены (задержание)
```
> «Статей» игра автоматом не даёт — поэтому в MVP дело описывается тем, что есть
> (розыск/права/штрафы/локация). Детальные статьи — опция на будущее (форма), если захочешь.

## 6. Discord (webhook)

```
На арест → embed в канал #уголовные-дела:
  Заголовок: «Рапорт о задержании · Дело #NNN»
  Поля: Подозреваемый · Статус (розыск/права) · Район · Время · Офицер (позывной)
  Вложение: скриншот сцены
  Цвет: по статусу (розыск — красный, обычное — синий)
Webhook сообщества хранится на СЕРВЕРЕ (не в клиенте).
```

## 7. Сайт (дашборд сообщества)

```
Страницы:
  - Главная: последние дела, счётчики (сегодня/неделя), топ офицеров.
  - Профиль офицера: позывной, статистика (аресты, дела), список его дел «что сделал».
  - Реестр дел: фильтры (офицер/статус/дата), карточка дела.
  - Карточка дела: данные + скрин + статус + история статусов (Подано→В суде→Приговор→Закрыто).
Статусы дел меняются вручную на сайте (кнопки) — для «судебных дел».
```

## 8. Модель данных (упрощённая для MVP)

```
Officer:  id, callsign, name, arrests_count, cases_count
Case:     id, officer_id, suspect_name, wanted(bool), license_state, citations,
          zone, postal, game_time, created_at, screenshot_path, status
Status:   submitted | under_review | in_court | convicted | dismissed | closed
StatusLog: case_id, status, changed_at   (история для судебных дел)
```
Для одного сообщества хватит **SQLite** (просто, файловая БД, ноль настройки).

## 9. Стек (минимальный, под быстрый старт)

```
Мод:     C# / .NET Framework 4.8, LSPDFR-плагин (как карьерный — тот же каркас).
API+БД:  Python FastAPI + SQLite. Эндпоинты: POST /case, GET /cases, PATCH /case/{id}/status.
Discord: webhook (requests POST).
Сайт:    простой веб — FastAPI отдаёт HTML-шаблоны (Jinja) ИЛИ лёгкий SPA. Для MVP — шаблоны.
Скрины:  файлы на сервере (папка) + путь в БД. Позже — облачное хранилище.
```

## 11. Этапы реализации — ВАЖНО: веб-часть можно начать СЕЙЧАС

> Мод упирается в `RagePluginHookAPI.dll` (нужен для сборки). **А API + сайт от этого НЕ зависят** —
> их можно писать и тестировать локально прямо сейчас, без игры и без блокера.

```
Этап 1 (можно сейчас, без игры): API + БД + Discord webhook + простой сайт.
        Тестируем «фейковым» POST /case (как будто мод прислал) → появляется в Discord и на сайте.
Этап 2: сайт-дашборд (профили офицеров, реестр, карточка дела, статусы).
Этап 3 (когда решим блокер мода): мод — детект ареста + сбор данных + скрин + отправка в API.
        Ставится рядом с Vinewood, тестим в игре.
Этап 4: шлифовка (фильтры, статистика, оформление карточки/embed).
```

**Рекомендация:** начать с **Этапа 1** — он даёт видимый результат (дело в Discord + на сайте)
уже сейчас, локально, за $0, и не ждёт разблокировки мода.
