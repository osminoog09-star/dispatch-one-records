# Рапорты, Discord и онлайн-платформа статистики (Dispatch One: Records)

**Назначение:** автоматизировать арест-рапорты → Discord сообщества + центральный сайт со
статистикой офицеров и статусами дел, куда другие игроки тоже шлют данные автоматически.
**Статус:** дизайн на бумаге (по просьбе — сначала продумать, потом делать).

---

## 1. Что хочет пользователь (ТЗ его словами → структурировано)

```
1. Сейчас вручную: скриншот рапорта о задержании + описание → в Discord-канал #уголовные-дела.
2. Хочу: автоматизировать — мод сам красиво и правильно отправляет это в тот чат.
   (есть проблема с кириллицей — скрин будет позже)
3. Онлайн-сайт: вся статистика собирается туда. Другие игроки, поставив мод, тоже
   автоматом шлют. На сайте — смотреть, что и как сделал сотрудник, статусы судебных дел.
4. Сначала всё на бумаге.
+ (отдельно) напарник тупой — тоже надо что-то придумать. → см. §12 (отдельная тема).
```

## 2. Что это по сути + конкуренты

По сути это **CAD/MDT-система** (Computer Aided Dispatch / Mobile Data Terminal) — цифровой
полицейский документооборот: рапорты, дела, профили офицеров, статистика.

| Продукт | Что есть | Слабость для нас |
|---|---|---|
| **NexusMDT** | MDT + сайт, публичные профили офицеров, лог инцидентов, лидерборд | Отдельный продукт, не связан с картой/диспетчером, EN |
| **MDTPro** | Рапорты: арест/инцидент/штраф/изъятие | Только рапорты, без единой экосистемы |
| **ReportsPlus** | Внешний MDT на 2-м устройстве, реальные данные игры | Локально, без центрального сайта сообщества |
| **Policer Advanced** | Evidence + XP/ранги за аресты + Discord | Своя система, не наша |

**Вывод:** «ещё один MDT» не нужен — их хватает. Наш клин: **это часть единой Dispatch One**
(карьера + AI-диспетчер + рапорты + сайт), заточенная под **авто-workflow твоего сообщества
в Discord**, RU, с привязкой к карьерной статистике и делам. Не отдельный инструмент, а слой
одной экосистемы.

## 3. Ключевой технический вывод (решает и проблему кириллицы)

> **Слать ДАННЫЕ, а не скриншот.**

Сейчас проблема: скриншот игрового рапорта → шрифт GTA не рендерит кириллицу (кракозябры).
Если мод отправляет **структурированные данные** (кого, за что, когда, где, статьи, офицер),
а красивый рапорт рендерится уже **в Discord (embed) и на сайте** — там нормальные шрифты,
кириллица работает идеально, и выглядит аккуратно и единообразно.

```
Плохо:  игра рисует рапорт → скриншот (кракозябры) → в Discord картинкой
Хорошо: мод собирает ДАННЫЕ → API → красивый рапорт в Discord-embed + на сайте (кириллица ОК)
```
Скриншот можно прикладывать опционально (как доп. фото сцены), но сам рапорт — данными.

## 4. Архитектура

```
   ИГРА (LSPDFR-плагин Dispatch One)
     │  собирает данные ареста: Persona (имя, розыск), статьи, время, район, офицер, фото(опц.)
     ▼
   [наш API / бэкенд]  ──►  Discord (webhook/бот сообщества): красивый embed-рапорт
     │
     ├─►  БД: офицеры, рапорты, дела, статусы, сообщества
     │
     ▼
   ОНЛАЙН-САЙТ (дашборд сообщества)
     - профиль офицера: что и как сделал, статистика
     - реестр дел + статусы судебных дел
     - лидерборд, история
     ▲
     └── другие игроки со своим модом шлют данные в СВОЁ сообщество (мульти-тенант)
```

Тот же бэкенд, что «мозг» диспетчера, может хостить и это (или отдельный сервис Records).
Мод шлёт в API (не напрямую в Discord) → API пишет в БД + постит в Discord. Централизованно,
безопасно, есть сайт.

## 5. Поток «арест → рапорт»

```
1. Игрок арестовал (детект как в карьере: IsPedArrested / IsPlayerArresting — poll-движок).
2. Мод собирает данные:
   - Persona: имя, пол, дата рожд., Wanted, ELicenseState, Citations
   - статьи/причина задержания (выбор игроком из списка или ручной ввод)
   - время (игровое), район (GetZoneAtPosition), почтовый индекс (CalloutInterface.GetPostalCode)
   - офицер: позывной + профиль карьеры (7-WILLIAM-1, звание)
   - опц. скриншот сцены
3. Мод показывает форму рапорта (RAGENativeUI) → игрок подтверждает/дополняет.
4. Мод → API: POST /report (данные ареста).
5. API: пишет в БД (создаёт «дело»), постит embed в Discord-канал сообщества, обновляет статистику.
6. Дело появляется на сайте со статусом «Подано».
```

## 6. Discord-интеграция

```
Вариант A (MVP) — Webhook:
  + Просто: POST JSON с embed в URL вебхука канала.
  + Красивый rich-embed: заголовок «Рапорт о задержании», поля (кого, статьи, офицер, время),
    цвет по типу, опц. картинка-вложение.
  - Односторонний (только постим), URL хранить на СЕРВЕРЕ (не в клиенте — см. LAUNCHER-AND-SECURITY).

Вариант B (позже) — Discord-бот:
  + Двусторонний: команды, обновление статуса дела прямо в Discord, роли/права.
  + Ветки-треды под каждое дело, статусы судебных дел ставятся в Discord и синкаются на сайт.
  - Сложнее: хостинг бота, токен, права.

Старт: Webhook (быстро, ценно). Бот — когда нужен интерактив и статусы из Discord.
```

Настройка на сообщество: каждый Discord-сервер задаёт свой webhook/ключ сообщества (в конфиге
мода или на сайте), чтобы данные шли в ИХ канал и ИХ пространство на сайте.

## 7. Модель данных

```
Community (сообщество/департамент)
  id, name, discord_webhook (на сервере!), site_slug, join_key

Officer
  id, community_id, callsign (7-WILLIAM-1), name, rank, xp, linked_discord_id
  (тянется из карьерного профиля — CAREER-MOD-DESIGN)

ArrestReport / Case (дело)
  id, community_id, officer_id, suspect_name, charges[], location, postal, game_time,
  created_at, screenshot_url(опц.), narrative(текст),
  status: submitted | under_review | in_court | convicted | dismissed | closed

CaseStatusHistory
  case_id, status, changed_by, changed_at, note   (для «статусов судебных дел»)

Stats (агрегаты офицера — можно считать на лету)
  arrests, reports, cases_by_status, activity_timeline
```

Статусы судебного дела = конечный автомат: `Подано → На рассмотрении → В суде → Приговор/Отклонено → Закрыто`.

## 8. Онлайн-сайт (дашборд сообщества)

```
Публично/по-ролям внутри сообщества:
  - Профиль офицера: позывной, звание, стаж, статистика (аресты, дела, активность),
    список его дел и их статусы — «что и как сделал сотрудник».
  - Реестр дел: фильтры по офицеру/статусу/дате, карточка дела (рапорт + история статусов).
  - Статусы судебных дел: доска (Подано/В суде/Приговор…), кто ведёт.
  - Лидерборд/активность (как NexusMDT, но в нашей экосистеме).
  - Мультиигрок: каждый со своим модом шлёт в своё сообщество; данные разделены (мульти-тенант).

Стек (черновик): бэкенд API (Python/FastAPI — как основной), БД PostgreSQL, фронт — веб (SPA).
Хостинг — общий с бэкендом Dispatch One (или отдельный сервис Records).
```

## 9. Мультиигроки / подключение других

```
- Игрок ставит мод → в настройках вводит КЛЮЧ СООБЩЕСТВА (или логинится на сайте, привязка).
- Его аресты/рапорты идут в пространство ЭТОГО сообщества (свой Discord-канал + свой раздел сайта).
- Разные сообщества изолированы (мульти-тенант, как аккаунты).
- Личный режим: игрок без сообщества — своя приватная статистика (только он видит).
```

## 10. Приватность и безопасность

```
- Webhook/ключи сообщества — на СЕРВЕРЕ, не в клиентском конфиге (см. LAUNCHER-AND-SECURITY).
- Мод шлёт в наш API по токену; API решает, куда постить.
- Данные сообщества видны по ролям (кто может смотреть чужие дела, менять статусы).
- Игровые данные вымышленные (Persona генерится игрой) — не реальные ПД, но всё равно
  разделяем по сообществам и не светим публично без настройки.
- Anti-abuse: rate-limit, валидация, чтобы не спамили в чужой канал.
```

## 11. Связь с остальной экосистемой Dispatch One

```
- Карьерный мод УЖЕ детектит аресты (poll-движок) → переиспользуем этот детект для рапортов.
- Профиль офицера (звание, статистика) — из карьерного профиля.
- AI-диспетчер может озвучивать: «Рапорт принят», «Дело №… передано в суд».
- Один клиентский мод — три функции: карьера + рапорты + (позже) диспетчер.
```

## 12. Тупой напарник и копы (отдельная тема — заметка)

```
Это НЕ про Discord/сайт, а про игровой AI. Базовый AI напарников/копов в GTA V слабый —
это движок, не глюк. Два пути:
  A. Готовые моды на AI (напарник умнее, лучше стреляет/водит/реагирует) — найти актуальные,
     проверить совместимость с текущей сборкой.
  B. Свой модуль поведения напарника (сложнее; можно связать с AI-диспетчером — «умный партнёр»).
→ Разобрать отдельно. Возможный будущий модуль Dispatch One: «AI-напарник» (голос + поведение),
  ещё один клин против конкурентов. Пока — заметка, не в этой фазе.
```

## 13. Этапность (сначала бумага → потом код)

```
Этап 0 (сейчас): этот дизайн на бумаге. ✓
Этап 1 (MVP, ценно быстро): арест → мод собирает данные → форма → API → красивый embed в Discord
        (данными, не скриншотом → кириллица решена). Без сайта, webhook сообщества.
Этап 2: БД + дела + статусы + простой сайт-дашборд (профиль офицера, реестр дел).
Этап 3: мульти-тенант (другие сообщества/игроки), роли, статусы судебных дел, лидерборд.
Этап 4: Discord-бот (интерактив, статусы из Discord), связка с AI-диспетчером.
```
