# AI-Диспетчер — Тех-документ Фазы 0 и Фазы 1

**Проект:** свой AI-диспетчер полиции для GTA V (конкурент Vinewood Hub)
**Дата:** 2026-07-19
**Охват документа:** Фаза 0 (бэкенд-«мозг») + Фаза 1 (фронт LSPDFR, одиночка)
**Цель фазы:** рабочий диспетчер у одного игрока в одиночной LSPDFR, на своём ключе/сервере, архитектурно готовый к подключению FiveM.

---

## 0. Главный принцип

**Один мозг — много фронтов.** Вся логика (распознавание речи, LLM, синтез голоса, команды, память смены) живёт в бэкенде на хостинге. Игра — только «тонкий переходник»: ловит микрофон, шлёт состояние игры, проигрывает голос, исполняет команды.

```
        ┌──────────────── БЭКЕНД (хостинг) ─────────────────┐
        │                                                    │
        │   WebSocket-шлюз                                   │
        │      │                                             │
        │      ├─ VoiceGate (Vosk/Silero VAD) — режет тишину │
        │      ├─ IBrain ◄─── Gemini Live  ИЛИ  локальный:   │
        │      │              (Whisper → LLM → TTS)          │
        │      ├─ ToolProtocol — парс команд из ответа LLM   │
        │      ├─ ShiftMemory — память смены                 │
        │      └─ ContextBuilder — собирает промпт-контекст  │
        │                                                    │
        └───────────────────────┬────────────────────────────┘
                                │ WebSocket (JSON + бинарный PCM)
                    ┌───────────┴───────────┐
              [LSPDFR DLL]            [FiveM resource]   ← Фаза 2
               Фаза 1                  (позже)
```

**Ключевое требование:** `IBrain` — это интерфейс. За ним прячется либо облачный Gemini, либо локальный каскад. Переключение — конфигом, без переписывания остального. Это даёт нам: старт на дешёвом pay-per-use облаке → переезд на свой GPU, когда появится нагрузка.

## 1. Технологический стек

| Слой | Выбор | Почему |
|---|---|---|
| **Бэкенд** | Python 3.11 + FastAPI + websockets | Весь AI-экосистем (faster-whisper, vLLM, TTS) — Python-нативный. Не придётся переписывать при переходе на локальные модели. |
| **Мозг (облако)** | Gemini `gemini-3.1-flash-live-preview` | Realtime voice-to-voice, дешевле всего на старте. Тот же мотор, что у конкурента. |
| **Мозг (локально, позже)** | Whisper (STT) + Qwen2.5-7B/LoRA (LLM) + Silero/XTTS (TTS) | Ноль стоимости за минуту. Задача узкая → малая модель справляется. |
| **VAD/гейт** | Silero VAD (или Vosk) | Не гнать тишину в облако = прямая экономия. |
| **Фронт LSPDFR** | C# / .NET Framework 4.8, плагин RagePluginHook | Обязательная среда LSPDFR. У нас есть опыт .NET-моддинга. |
| **Аудио на клиенте** | NAudio (WASAPI) | Захват микрофона PCM 16 кГц + воспроизведение. |
| **Транспорт** | WebSocket, JSON для сообщений + бинарные кадры для PCM | Стандарт для realtime-аудио. |

## 2. Фаза 0 — Бэкенд-«мозг»

### 2.1. Интерфейс мозга (`IBrain`)

Абстракция, за которой Gemini и локальный каскад взаимозаменяемы.

```
IBrain
  session = start_session(context: GameContext, persona: Persona) -> BrainSession

BrainSession
  send_audio(pcm: bytes)            # входящий звук с рации офицера
  update_context(delta: dict)       # игра прислала новое состояние
  on_audio_out(cb)                  # готовый голос диспетчера (PCM) -> проиграть в игре
  on_tool_call(cb)                  # структурная команда -> исполнить в игре
  on_transcript(cb)                 # опц. текст реплики (для субтитров/логов)
  push_tool_result(result: dict)    # игра вернула результат (напр. пробитый номер)
  end_session()
```

**GeminiBrain** — реализует через Live API WebSocket (`wss://.../BidiGenerateContent`), стримит PCM туда/обратно, системный промпт ставит один раз на сессию.

**LocalBrain** (Фаза 3+) — каскад: VAD → Whisper (текст) → LLM (ответ + токены команд) → TTS (голос). Тот же интерфейс наружу.

### 2.2. Протокол WebSocket (игра ⇆ бэкенд)

**Клиент → Бэкенд:**

| Тип | Данные | Когда |
|---|---|---|
| `hello` | `{auth, game:"lspdfr", persona_pref, sample_rate:16000}` | При подключении |
| *(binary)* | PCM16 16кГц кадры | Пока зажат PTT (после гейта VAD) |
| `ptt` | `{state:"down"/"up"}` | Нажатие/отпускание клавиши рации |
| `context` | GameContext (см. 2.5) | По изменению состояния (район, погоня, вызов) |
| `tool_result` | `{tool, id, result:{...}}` | После исполнения команды (напр. результат пробива) |

**Бэкенд → Клиент:**

| Тип | Данные | Действие клиента |
|---|---|---|
| `ready` | `{persona, callsign}` | Сессия готова |
| *(binary)* | PCM16 кадры голоса диспетчера | Проиграть через NAudio |
| `tool_call` | `{tool, id, args:{...}}` | Исполнить в LSPDFR (см. 3.4) |
| `transcript` | `{role, text}` | Опц.: субтитры/лог |
| `error` | `{code, message}` | Показать/залогировать |

### 2.3. Протокол команд (Tool Protocol)

LLM в ответе пишет псевдо-функции, бэкенд их парсит и превращает в структурные `tool_call`. Формат (как у конкурента, регуляркой): `ИмяКоманды{ключ:значение, ключ:значение}`.

**Стартовый набор команд Фазы 1** (минимум для играбельности):

| Команда | Аргументы | Смысл |
|---|---|---|
| `RequestBackup` | `units, code` | Вызов подкрепления (code 1/2/3) |
| `PursuitBackup` | `code` | Подкрепление в погоню |
| `StatusCheck` | `status` | Смена статуса (10-8 на службе / 10-7 нет) |
| `PlateRun` | `plate` | Пробить номер машины |
| `NameRun` | `name` | Пробить имя/личность |
| `DispatchCallout` | `type` | Выдать игроку вызов |
| `Advisory` | `text` | Просто сообщение по рации (без действия) |

**Полный набор (Фаза 2+, есть у конкурента, знаем сигнатуры):** AirSupport, Canine/K9, SpikeStrips, PIT, EMS, Fire, Coroner, Roadblock, FelonyStop, Bolo, DismissUnits, AuthorizePursuit, InitiatePursuit, TrafficStopBackup.

**Двусторонность:** команды типа `PlateRun`/`NameRun` требуют ответа. Поток: LLM → `tool_call PlateRun{plate:"5ABC123"}` → клиент исполняет/генерит результат → `tool_result{result:{owner, wanted, ...}}` → бэкенд отдаёт результат в контекст LLM → диспетчер зачитывает пробитое по рации.

### 2.4. Память смены (ShiftMemory) — наше отличие №1

У конкурента диспетчер не помнит контекст. У нас — помнит.

- **Событийный лог смены** (append-only): начало смены, каждый вызов (тип, район, исход), остановки, погони, ключевые реплики.
- **Скользящая сводка**: последние N событий + краткое summary старых → вставляется в контекст LLM блоком «ПАМЯТЬ СМЕНЫ».
- Эффект: диспетчер ссылается на прошлые вызовы («это тот же адрес, что полчаса назад»), ведёт сквозную линию смены, узнаёт повторные ситуации.

Хранение: в оперативке на сессию + опц. дамп в JSON на диск для «непрерывной службы» между сессиями.

### 2.5. GameContext (снапшот состояния для LLM)

Клиент шлёт это при изменениях; бэкенд вставляет в контекст. Поля (из декомпила LSPDFR-функций):

```
{
  agency: "LSPD" | "BCSO" | "SAHP",   // GetCurrentAgencyScriptName
  callsign: "2-Adam-12",              // генерится на сессию
  zone: "Vinewood Hills",             // GetZoneAtPosition
  postal: "1234",                     // GetPostalCode
  on_duty: true,
  active_callout: null | "TrafficStop",  // IsCalloutRunning / GetCurrentCallout
  in_pursuit: false,                     // GetActivePursuit != null
  time_of_day: "23:40",
  area_hint: "фривей / город / глушь"
}
```

### 2.6. Персонажи (Persona)

Пул диспетчеров (у конкурента 8). Каждый — блок характера в промпте + выбор голоса. Ротация между сменами. Фаза 1: 2-3 персонажа достаточно.

### 2.7. Черновик системного промпта

Скелет (расширяется до уровня их ~60К, но структура такая). **Урок из их версии 1.3.1: ровный профессионал по умолчанию, без переигранных эмоций.**

```
Ты — диспетчер полиции Лос-Сантоса (округ Блэйн, штат Сан-Андреас).
Ты ведёшь радиообмен с патрульными экипажами LSPD, BCSO, SAHP.
Ты живой опытный человек за пультом, не AI-помощник.

# ЯЗЫК
- Говоришь ТОЛЬКО на чистом русском. Это русский дубляж американской полицейской рации.
- Тип происшествия — обычными словами: «жалоба на шум», «семейная ссора», не номером.
- Понимаешь все радиокоды офицера (10-4, код 1/2/3, 10-8, 11-99). Сам держись простой речи,
  но распространённые коды произносить можно: «десять-четыре», «код три».
- Числа/адреса/годы — словами. Буквы — фонетикой НАТО по-русски (Альфа, Браво, Чарли).

# ГОЛОС (главное)
- Ровный, уверенный голос профессионала: спокойно, чётко, по-деловому,
  нейтрально-доброжелательно. БЕЗ грусти, БЕЗ наигранной усталости, БЕЗ театральности.
- На серьёзном вызове — собраннее и твёрже, но без крика и паники.

# ПРОЦЕДУРА ЭФИРА
- Сначала позывной экипажа, потом сообщение. Подтверждая — повторяй позывной.
- Кратко. Одна мысль — одна передача.
- Подтверждение по умолчанию — «принято» / «вас понял» / «записал».

# КОМАНДЫ (как ты управляешь миром)
Когда по ситуации нужно действие, добавь в конце реплики токен:
  RequestBackup{units:2, code:3}   — вызвать подкрепление
  StatusCheck{status:"10-8"}       — сменить статус экипажа
  PlateRun{plate:"5ABC123"}        — пробить номер
  ... (полный список ниже)
Токен не произносится вслух, это команда системе.

# ПАМЯТЬ СМЕНЫ
{сюда бэкенд вставляет сводку последних событий}

# ТЕКУЩАЯ ОБСТАНОВКА
{сюда бэкенд вставляет GameContext}

# ТВОЙ ПЕРСОНАЖ
{сюда вставляется блок выбранного персонажа}
```

## 3. Фаза 1 — Фронт LSPDFR (клиентский DLL)

Тонкий плагин: захват звука + состояние игры → бэкенд → голос + исполнение команд. **Никакой логики LLM на клиенте.**

### 3.1. Структура проекта

```
AIDispatcher.LSPDFR/         (.NET Framework 4.8, class library -> .dll в plugins/LSPDFR)
  EntryPoint.cs              — Plugin: Initialize/Finally, подписки LSPDFR
  Config.cs                  — чтение .ini (адрес бэкенда, PTT-клавиша, устройство, громкость)
  Audio/
    MicCapture.cs            — NAudio WASAPI, PTT, PCM16 16кГц
    VoicePlayer.cs           — проигрывание PCM из бэкенда
  Net/
    BackendClient.cs         — WebSocket к бэкенду, отправка аудио/контекста, приём голоса/команд
  Game/
    ContextProvider.cs       — сбор GameContext из LSPDFR Functions
    ToolExecutor.cs          — исполнение tool_call через LSPDFR API
  deps/                      — NAudio, зависимости (как у конкурента)
```

### 3.2. Клавиша рации (PTT)

- По умолчанию правый Alt (как у конкурента: RMenu). Настраивается в .ini.
- Зажата → захват микрофона + `ptt:down` + стрим PCM. Отпущена → `ptt:up`.
- Опц. звук нажатия рации (chirp) — у конкурента есть key_down/key_up/ptt_chirp.wav.

### 3.3. Сбор контекста (`ContextProvider`)

Читает из LSPDFR API и шлёт `context` при изменениях:

| Поле | Источник LSPDFR |
|---|---|
| agency | `Functions.GetCurrentAgencyScriptName()` |
| zone | `Functions.GetZoneAtPosition(playerPos)` |
| postal | `Functions.GetPostalCode(playerPos)` |
| active_callout | `Functions.IsCalloutRunning()` / `GetCurrentCallout()` |
| in_pursuit | `Functions.GetActivePursuit() != null` |
| callsign | генерится на сессию (напр. «N-Adam-NN») |

### 3.4. Исполнение команд (`ToolExecutor`)

Маппинг `tool_call` → реальные вызовы LSPDFR (сигнатуры из декомпила):

| tool_call | Вызов LSPDFR |
|---|---|
| `RequestBackup{units, code}` | `Functions.RequestBackup(pos, EBackupResponseType, EBackupUnitType)` |
| `PursuitBackup{code}` | `RequestBackup` с типом под погоню |
| `StatusCheck{status}` | `Functions.SetPlayerAvailableForCalls(bool)` |
| `DispatchCallout{type}` | `Functions.StartCallout(name)` |
| `PlateRun` / `NameRun` | сгенерить результат (или взять из Grammar Police/CDF) → `tool_result` |
| `Advisory{text}` | ничего в игре / опц. скан-аудио |

> Точные сигнатуры `EBackupResponseType`/`EBackupUnitType` и т.п. добываем приёмом рефлексии из [[autotrader-reflect-dll-signatures]] по `LSPD First Response.dll` — без запуска игры.

### 3.5. Конфиг (`AIDispatcher.ini`)

```
[Backend]
Url=wss://твой-хостинг:port/dispatch
AuthToken=...

[Keybind]
PTTKey=RMenu
PTTModifier=None

[Audio]
DeviceIndex=0
Volume=0.42

[Persona]
Mode=random   ; random | fixed
FixedName=

[Debug]
LogVerbose=false
```

## 4. Что делает нас лучше Vinewood (заложено в архитектуру)

1. **Память смены** — сквозная линия, ссылки на прошлые вызовы. У них нет.
2. **Мозг-агностик** — Gemini сегодня, своя LLM завтра; не заперты в одном вендоре. У них — только Gemini.
3. **Открытость / локальный режим** — работа на своём ключе или своём GPU, без вечной подписки за минуты. У них — только закрытое облако.
4. **Ровный профессионализм голоса сразу** — их же вывод из 1.3.1, применён с первого дня, но с переключателем «живого» тона.
5. **Два фронта из одного мозга** — одиночка + FiveM. У них — только одиночка.

## 5. Порядок работ Фазы 1 (вехи, каждая тестируется в игре)

1. **Каркас плагина** — грузится в RPH, читает .ini, логирует. *(тест: видно в лог)*
2. **PTT + захват микрофона** — зажал клавишу, пишется PCM. *(тест: сохранить wav, проверить звук)*
3. **BackendClient + эхо** — бэкенд-заглушка принимает аудио и шлёт назад голос. *(тест: «алё, слышно?»)*
4. **GeminiBrain в бэкенде** — реальный диалог голосом с промптом. *(тест: разговор с диспетчером)*
5. **GameContext** — диспетчер знает район/агентство/погоню. *(тест: назвать локацию — он в курсе)*
6. **Команды (стартовый набор)** — RequestBackup, StatusCheck, DispatchCallout, PlateRun, NameRun. *(тест: «пришлите подкрепление» → приехали)*
7. **ShiftMemory** — ссылки на прошлые события. *(тест: два вызова подряд, второй — с отсылкой к первому)*
8. **Персонажи + шлифовка промпта** — 2-3 характера, ровный голос.

> Тестовые заходы в игру — **пачками**: под каждую веху заранее готовим набор проверок, чтобы один запуск закрывал максимум (см. [[minimize-blind-iterations]] — не жечь итерации вслепую).

## 7. Экономика (справочно)

- **Gemini `gemini-3.1-flash-live-preview`:** вход ~$0.005/мин, выход ~$0.018/мин, текст $0.50/1M.
- **Себестоимость:** ~$0.22–0.57 за час активной игры.
- **Свой GPU:** $220–1100/мес за карту 24/7 — выгоден только при высокой постоянной загрузке; на старте облако дешевле (платишь за использование, без простоя).
- **Стратегия:** старт на облаке → свой GPU, когда объём докажет смысл. Не покупать железо раньше нагрузки.
```
