# Чек-листы тестов по вехам (батчами)

**Принцип:** каждый заход в игру дорог по времени → под каждую веху заранее собран
набор проверок, чтобы ОДИН запуск закрывал максимум. Не тестировать по одному вслепую.

Легенда: ☐ проверить · подготовка = что настроить ДО запуска игры.

---

## Веха 1 — Каркас плагина грузится
Подготовка: собрать DLL, положить в plugins\LSPDFR, .ini с dummy-значениями.
```
☐ RagePluginHook стартует без ошибок в RagePluginHook.log
☐ В логе есть «[AIDispatcher] loaded»
☐ Плагин не роняет другие моды (LSPDFR грузится, вызовы работают)
☐ .ini читается (лог показывает прочитанные значения: Url, PTTKey)
☐ Выход/вход на смену вызывает OnDuty-хендлер (лог «session start/stop»)
```

## Веха 2 — Захват микрофона по PTT
Подготовка: MicCapture пишет PCM в файл для проверки.
```
☐ Зажатие PTT (RMenu) начинает захват (лог «ptt down»)
☐ Отпускание — стоп (лог «ptt up», N чанков)
☐ Записанный wav воспроизводится, голос чистый, 16кГц
☐ Правильное устройство (Arctis Nova Pro) выбирается по DeviceIndex/Name
☐ Громкость/уровень адекватны (не тихо/не клип)
```

## Веха 3 — Связь с бэкендом (эхо-заглушка)
Подготовка: бэкенд-заглушка на localhost:8080 принимает аудио и шлёт назад тестовый PCM.
```
☐ ClientWebSocket коннектится к ws://localhost:8080/dispatch
☐ hello уходит, ready приходит
☐ PCM-чанки доходят до бэкенда (лог бэкенда: bytes received)
☐ Ответный PCM проигрывается в игре (VoicePlayer)
☐ Обрыв связи обрабатывается (реконнект/лог, без краша игры)
```

## Веха 4 — Реальный Gemini (диалог голосом)
Подготовка: BRAIN=gemini, free-tier ключ, промпт v1 подключён.
```
☐ setup уходит, приходит setupComplete
☐ Сказать «диспетчер, как слышно?» → осмысленный голосовой ответ по-русски
☐ Голос ровный, профессиональный (не театральный) — проверка блока 4
☐ Ответ приходит с адекватной задержкой (~1-2 сек)
☐ Числа/буквы произносятся по правилам (словами/фонетикой) — сказать номер
☐ Транскрипт логируется (inputAudioTranscription/output)
☐ Стоимость за тест видна и в рамках free-tier
```

## Веха 5 — GameContext (диспетчер знает обстановку)
Подготовка: ContextProvider шлёт agency/zone/pursuit/callout.
```
☐ Спросить «где я?» → называет текущий район (GetZoneAtPosition)
☐ Диспетчер знает агентство (LSPD/BCSO/SAHP) — тон соответствует
☐ Во время погони — реагирует иначе (in_pursuit=true в контексте)
☐ Контекст обновляется при смене района (clientContent-инъекция)
☐ Позывной постоянен в течение смены
```

## Веха 6 — Команды (стартовый набор)
Подготовка: ToolExecutor подключён, все 7 команд.
```
☐ «Пришлите подкрепление, два экипажа» → RequestBackup → машины приезжают
☐ code 3 vs code 2 различаются (сирены/скорость)
☐ «Я на службе / вне службы» → StatusCheck → доступность меняется
☐ «Пробей номер 5-Адам-Браво-Чарли» → PlateRun → результат зачитан по рации
☐ «Пробей имя» → NameRun → статус (розыск/права) озвучен
☐ «Дай вызов» → DispatchCallout → callout стартует
☐ Токены НЕ произносятся вслух
☐ Неизвестная команда игнорируется без краша
```

## Веха 7 — Память смены
Подготовка: ShiftMemory включён.
```
☐ Два вызова подряд → на втором диспетчер ссылается на первый
☐ Повторный адрес узнаётся («тот же адрес, что раньше»)
☐ Сводка смены не ломает промпт (влезает в контекст)
☐ Память не спамит контекст (обновление не чаще N сек)
```

## Веха 8 — Персонажи и шлифовка
```
☐ Разные персонажи звучат по-разному (голос/манера)
☐ Персонаж не ломает язык/коды/процедуру
☐ Ротация между сменами работает
☐ Общее впечатление: «живой диспетчер», лучше конкурента по связности
```

---

## Сводная стратегия экономии заходов
```
- Каждую веху тестировать ЦЕЛИКОМ за один заход (все ☐ подряд).
- Диагностику писать в лог заранее (не гадать постфактум).
- Групповать: вехи 1-3 можно проверить почти без игры (заглушки/файлы).
- В игру заходить, когда готов батч 4-8; собирать заметки по всем пунктам за раз.
```
