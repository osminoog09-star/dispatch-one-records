# Бриф для Codex: переделка лаунчера (разделы + инструкция + онбординг + onedir)

Автор брифа: Claude, 2026-08-06. Задачу по лаунчеру ведёт Codex.
Источник: пользователь. Дословно: «тут всё в 1 окне слишком много и не красиво,
надо сделать типа настройки и т.д., чтобы у каждой вещи было своё место; сейчас всё
на 1 странице — грязь и непонятно. Также нужна инструкция, как всё работает, чтобы люди
понимали, и при первом запуске они должны с ней ознакомиться.»

## 1. Проблема

Сейчас `launcher/launcher.py` рисует ВСЁ на одном экране подряд: баннер, версия,
профиль офицера, блок обновления, «АГЕНТ СИНХРОНИЗАЦИИ», «Написать в поддержку», «ИГРАТЬ».
Пользователю тесно и непонятно, что важно, а что второстепенно.

## 2. Цель

Разнести функциональность по разделам, чтобы у каждой вещи было своё место.
Первый экран — простой: играть. Всё остальное — по вкладкам/разделам.

## 3. Предлагаемая структура (вкладки или левое меню)

Реализация в tkinter: либо `ttk.Notebook` (вкладки сверху), либо левое меню из кнопок,
переключающее `Frame`-ы. Разделы:

1. **Главная / Играть**
   - Баннер LAPD (мигалки).
   - Статус: игра найдена/нет, агент вкл/выкл.
   - Большая кнопка **ИГРАТЬ** (ставит плагин, запускает через Vinewood, синхронизацию).
   - Короткая подпись, что произойдёт по нажатию.
2. **Профиль офицера**
   - Позывной, имя офицера, кнопка «Сохранить и прописать в игру».
   - Подсказка: позывной должен точно совпадать с ростером (пример `7-WILLIAM-1`,
     а НЕ `7 - WILIAM - 1`), иначе записи уйдут «на модерацию».
3. **Агент синхронизации**
   - Автозапуск с Windows, «Закрывать агент вместе с лаунчером».
   - Кнопки «Включить агент» / «Выключить агент», статус процесса.
   - «Открыть логи».
4. **Поддержка**
   - Чат в поддержку + авто-приложение RPH-лога.
   - (на будущее) кнопка «Проверить логи» — rule-based диагностика.
5. **Настройки**
   - Пути к игре и Vinewood (авто-поиск + ручной выбор).
   - Обновления (ставятся сами при запуске — показать статус/версию).
   - (на будущее) кнопка «Починить» — самолечение.
6. **Инструкция / Как это работает** (см. п.4)

Существующую логику НЕ терять: `play()`, `install_plugin()`, `start_agent()/stop_agent()`,
`support_chat`, авто-обновление, авто-поиск игры/Vinewood, `_fit_height` — всё переносится
в соответствующие разделы, только UI перекладывается.

## 4. Инструкция (контент раздела «Как это работает»)

Простым языком, по-русски:

- **Что это.** LAPD Records — лаунчер, который запускает GTA V (LSPDFR) через Vinewood,
  ставит плагин учёта и синхронизирует твою полицейскую активность на сайт.
- **Профиль.** Впиши позывной и имя офицера — они должны совпадать с ростером сервера.
- **Агент.** Фоновая программа `pdcomp_sync`: ловит игру, читает pdComp и отправляет данные
  на сайт. Может стартовать с Windows и закрываться вместе с лаунчером.
- **Как играть.** Жми ИГРАТЬ — лаунчер поставит плагин, запустит игру через Vinewood и
  включит синхронизацию. Играй как обычно; после выхода из игры данные появятся на сайте.
- **Где мои записи.** На сайте в профиле по твоему позывному (аресты, штрафы, вызовы, суды).
- **Логи и поддержка.** Кнопка «Открыть логи» и раздел «Поддержка» с приложением RPH-лога.
- **Если ничего не появилось.** Проверь позывной, что агент включён, и что ты выходил из игры.

## 5. Онбординг при первом запуске

- Хранить флаг в конфиге лаунчера (тот же файл настроек, где пути/автозапуск), напр.
  ключ `onboarding_done: bool`.
- Если флага нет / `false` → при старте показать экран/модалку «Добро пожаловать»
  с инструкцией из п.4 и кнопкой «Понятно, начать».
- По нажатию — выставить `onboarding_done = true`, больше не показывать.
- В разделе «Инструкция» инструкция доступна всегда (можно перечитать).

## 6. Фикс ошибки «Failed to load Python DLL» (важно, отдельно от UI)

У игроков повторяется:
`Failed to load Python DLL 'C:\Users\...\AppData\Local\Temp\_MEI...\python314.dll'.
LoadLibrary: Не найден указанный модуль.`

Причина: сборка `--onefile`. PyInstaller при каждом запуске распаковывает `python314.dll`
во временную `_MEI...`; антивирус/очистка temp удаляет её до загрузки → лаунчер не стартует.

**Лечение — пересобрать в `--onedir` (без `--onefile`).** Тогда `python314.dll` лежит в папке
рядом с exe и не распаковывается в temp. В релиз идёт папка (или self-extracting архив),
а не одиночный .exe.

- Обновить `launcher/BUILD.md` под onedir.
- Обновить путь ассета в GitHub Release и в `version.json` `launcher_url` (если раздаём папку/архив).
- Сохранить `--add-data` баннеров/DLL, `--add-binary pdcomp_sync.exe`,
  `--hidden-import embedded_token --hidden-import gateway_config`.
- Приватные `embedded_token.py` / `gateway_config.py` не коммитить.
